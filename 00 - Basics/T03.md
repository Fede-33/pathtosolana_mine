# ANCHOR
Es un framework de desarrollo en Solana que contiene librerías para reutilizar código (boilerplate) y no necesitar escribir programas desde cero en cada proyecto. Por ejemplo, validación de cuentas, manejo de erroes o serialización/deserialización de datos. En resumen, Anchor abstrae y automatiza las tareas de bajo nivel y repetitivas, haciendo que la experiencia de desarrollo de programas de Solana sea mucho más rápida, segura y menos propensa a errores. 

## SEGURIDAD
Anchor gestiona los **default security checks** y permite definir otros personalizados, a través de una API **constraints** separada de la lógica del programa en sí. 

## INICIO
El comando **anchor init new_project** inicializa un repositorio llamado "new_project" con todas las dependencias requeridas para comenzar a desarrollar en Solana. Este comando genera tres componentes:

1. **Módulo del programa:** El primer bloque de código define el módulo principal del programa, donde reside la **business logic** (lógica de negocio), que es el programa propiamente dicho:

        01 #[program]
        02 mod hello_anchor {
        03     use super::*;
        04     pub fn initialize(_ctx: Context<Initialize>) -> Result<()> {
        05         Ok(())
        06     }
        07 }

    * **01**  El atributo de Anchor **#[program]** indica que el módulo **mod hello_anchor** contiene la lógica del programa principal. El runtime de Anchor lo usa para generar el código boilerplate necesario para ejecutar tu programa.
    * **03** el módulo **hello_anchor** está importando todos los elementos públicos del módulo padre, que es el archivo principal donde el módulo está declarado. Es fundamental porque las **structs** que definen las cuentas y la macro **declare_id!** no están dentro del módulo del programa. 
    * **04** La primera función que se ejecuta en el programa es **initialize**. Lleva ese nombre por convención. **_ctx: Context<Initialize>** El Context es un tipo de datos especial de Anchor que agrupa todas las cuentas que se le pasan a la instrucción. En lugar de recibir **program_id**, **accounts** e **instruction_data** por separado, Anchor los empaqueta en este único tipo. El **Initialize** dentro de los corchetes angulares se refiere a la **Struct de cuentas**, previamente importada en la línea 03, el segundo componente que genera el comando anchor init. **Result<()>** Es el tipo de retorno de la función. Result es un tipo estándar de Rust para manejar errores, y el () indica que no se devuelve ningún valor si la función se ejecuta con éxito.
    * **05** Ok(()): Retorna un resultado exitoso.

2. **Struct de Cuentas (struct Initialize):** Es la API de **Constraints** de Anchor mencionada anteriormente:

        01 #[derive(Accounts)]
        02 pub struct Initialize {}
    
    * **01** Este atributo le dice a Anchor que la struct a continuación **(Initialize)** es un modelo de las cuentas que se le deben pasar a la instrucción. Cuando el programa se ejecuta, Anchor usa este modelo para validar automáticamente que todas las cuentas requeridas están presentes, son del tipo correcto, y tienen los permisos necesarios.
    * **02** definición de la **struct Initialize {}**, en este caso vacía. Hasta aquí la función initialize no requiere ninguna cuenta para operar. Si se quisiera, por ejemplo, inicializar una PDA, la cuenta se incluiría aquí.

3. **Macro declare_id!:** Macro de Anchor que define el ID del programa:

        declare_id!("Fg6Pa...");
    
    genera una variable de **Pubkey** que almacena la dirección única del programa. La cadena de texto **"Fg6Pa..."** es la clave pública del programa. Esta dirección se genera automáticamente por el comando anchor init y es fundamental para que el programa pueda ser invocado y para que otros programas o aplicaciones puedan interactuar con él. El ID se utiliza para las verificaciones de seguridad, por ejemplo, para asegurar que una PDA es propiedad de este programa específico.

## HELLO WORLD
El siguiente ejemplo es un código básico de Solana, escrito con Anchor. Cada una de las partes principales está diferenciada por comentarios:

    //Importa la librería Anchor
    use anchor_lang::prelude::*;
    
    //Macro delare_id! con el ID del programa
    declare_id!("Foj39PNzARZMXefHffK2iPFHdyEntaSVdmi5UgW4ub9M");
    
    //Módulo del programa
    #[program]
    pub mod hello_world {
        use super::*;
    
        pub fn initialize(ctx: Context<Initialize>) -> Result<()> {
            msg!("Hello World from Anchor", ctx.program_id);
            Ok(())
        }
    }
    
    //Validación Struct de Cuentas (struct Initialize) 
    #[derive(Accounts)]
    pub struct Initialize {}

## EJEMPLO PRÁCTICO
El siguiente programa de Anchor está diseñado para establecer un valor numérico (data) en una cuenta personalizada (MyAccount), pero solo si la cuenta de token asociada al usuario tiene un saldo positivo:

    01 use anchor_lang::prelude::*;
    02 
    03 declare_id!("Foj39PNzARZMXefHffK2iPFHdyEntaSVdmi5UgW4ub9M");
    04 
    05 #[program]
    06 mod hello_anchor {
    07     use super::*;
    08     pub fn set_data(ctx: Context<SetData>, data: u64) -> Result<()> {
    09         if ctx.accounts.token_account.amount > 0 {
    10             ctx.accounts.my_account.data = data;
    11         }
    12         Ok(())
    13     }
    14 }
    15 
    16 #[account]
    17 #[derive(Default)]
    18 pub struct MyAccount {
    19     data: u64
    20 } 
    21
    22 #[derive(Accounts)]
    23 pub struct SetData<'info> {
    24    #[account(mut)]
    25    pub my_account: Account<'info, MyAccount>,
    26    pub token_account: Account<'info, TokenAccount>, 
    27    pub signer: Signer<'info>,
    28 }
    29
    30 #[account]
    31 pub struct TokenAccount {
    32     pub mint: Pubkey,
    33     pub owner: Pubkey,
    34     pub amount: u64,
    35 }

* **01** Importación de la librería de Anchor.
* **03** Declaración del ID del programa.
* **05 - 07** Declaración del módulo del programa.
* **08** El Context **ctx: Context<SetData>** es una estructura que contiene las cuentas necesarias para la ejecución. **SetData** es la struct que define esas cuentas, y Anchor se asegura automáticamente de que sean válidas y estén en el orden correcto. El código define que **data** sea el valor que se guardará en la cuenta y **u64** el tipo de dato.
* **09** La condición **if ctx.accounts.token_account.amount > 0** es una validación de la lógica de negocio. El programa verifica si el saldo **(amount)** en la cuenta de token del usuario es mayor que 0.
* **10** Si el saldo es positivo se ejecuta **ctx.accounts.my_account.data = data;**. El programa toma el valor de **data** y lo asigna al campo **data** de la cuenta **my_account**. Aquí es donde se actualiza el estado en la cadena.
* **11**  El programa retorna Ok para indicar que la ejecución fue exitosa, independientemente de si el valor se actualizó o no.
* **16 - 19** Esta anotación le dice a Anchor que la struct **MyAccount** es un modelo de datos **#[account]** (cuenta en la cadena). **#[derive(Default)]** es un atributo que permite a Anchor inicializar la struct con valores predeterminados, en este caso, **data** se inicializaría en 0. **data: u64** define el único campo de la cuenta, un entero sin signo de 64 bits. 
* **22** Definición de la struct de contexto (validación de cuentas)
* **23** Se define con el trait **#[derive(Accounts)]** y contiene todas las cuentas que deben pasarse a la instrucción set_data.
* **24** El atributo **#[account(mut)]** le dice a Anchor que esta cuenta debe ser mutable (se puede escribir en ella).
* **25** Esta cuenta es de tipo **MyAccount** espeificado a través de **Account<'info, MyAccount>** y debe contener un modelo de datos **MyAccount** válido.
* **26** Se define **token_account** como una cuenta de tokens estándar, que el programa necesita para su validación.
* **27** Este campo le indica a Anchor que la transacción debe ser firmada por el propietario de esta cuenta. Es una validación de seguridad fundamental.
* **30** Definición de la struct de la cuenta de tokens **(struct TokenAccount)**. Si bien la estructura del token real es más compleja, esta es una simplificación para fines del ejemplo. Sin ella, el programa no podría acceder a **amount** en la línea de validación.

### Flujo de la Transacción:
En resumen, cuando un usuario envía una transacción para ejecutar la función **set_data**, el proceso es el siguiente:

1. El programa recibe la instrucción, el valor **data** y las cuentas necesarias (**token_account** y **MyAccount**).
2. Anchor valida que las cuentas son legítimas y están en orden, según lo definido en la struct **SetData**.
3. El programa verifica que el usuario tiene tokens en su cuenta.
4. Si el usuario tiene tokens, el programa actualiza el campo **data** de **MyAccount** con el nuevo valor.
5. El programa finaliza con éxito.
